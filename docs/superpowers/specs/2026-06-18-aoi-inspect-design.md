# AOI 实时在线 AI 质检系统 — 设计文档

> 2026 中国研究生人工智能大赛 · 华为赛题一 ·《可自学习的 AOI 实时在线 AI 质检》
> 日期:2026-06-18 · 截止:2026 年 8 月

## 1. 目标与成功标准

构建一套 AI 驱动的实时质检系统:在少样本/零样本条件下检测工业组件的外观异常、缺件少件、顺序/逻辑错误、尺寸偏差、色彩变化,支持图片与视频输入,并通过操作员反馈在线优化。

**评分结构(对齐赛题):**

| 组成 | 权重 | 我们的拿分抓手 |
|---|---|---|
| 竞赛 — 方案完整度 | 50% (×60%) | 多分支全系统 + Web Demo + 三份文档 + 消融实验 |
| 竞赛 — 答案准确率 | 20% (×60%) | 无监督异常检测分支在公开集上跑官方协议 |
| 竞赛 — 检测时间 | 30% (×60%) | 小模型 + OpenVINO,GPU <200ms / CPU <2s |
| 专家评分 | 40% | 零样本检测 + 主动学习闭环 + LLM 可解释性(三个新颖点) |

**可验证成功标准:**

1. `eval/protocol.py` 能复刻官方协议(100 正常 + 30 缺陷迁移 → 测 1000+),在 MVTec AD 上输出 image-AUROC / pixel-AUROC 与准确率得分。
2. 热路径单张 2500×2500 推理:GPU <200ms,OpenVINO CPU <2s,由 `deploy/` 延时基准脚本证明。
3. 跨域泛化:在数据集 A 上配置好,直接在数据集 B 上评测,泛化结果写入文档。
4. Web Demo 可演示:上传 → 热力图+判决 → 标记漏检 → 观察模型在线更新后该样本被正确召回。
5. 三份文档齐全:可解释性文档、使用说明、公开集结果报告。

## 2. 关键约束与设计决策(已与用户确认)

- **交付物 = 预训练权重 + `fit_fewshot()` 适配代码 + 推理代码 + 文档**,不是冻结的黑盒模型。评委用未知域的 100 正常 + 30 缺陷在其机器上现场调用 `fit_fewshot()` 做迁移,再测 1000+。
- 因此**首选记忆库类方法(PatchCore)**:其"迁移"= 把正常图喂入记忆库,无需梯度训练,现场快速、可复现。
- **非公开测试集拿不到也不需要**;开发期在公开集上用"模拟评测协议"验证泛化。
- **全类型检测**:外观异常 + 缺件 + 顺序/逻辑 + 尺寸,每类一个独立分支。
- **图片 + 视频**:视频按逐帧 + 时序平滑处理,逻辑/顺序错误由专用分支承担。
- **合成数据分两档**:轻量 Cut-Paste/Perlin(纳入 `fit_fewshot`,提分,做);重型 Diffusion 生成(仅训练期离线,作可选 novelty,核心不依赖)。
- **LLM 只在冷路径**(不计时):缺陷报告生成、反馈分诊、合成数据指导、逻辑语义复核。绝不进被计时的检测主路径。
- **交互形态**:轻量 Gradio Web Demo。

## 3. 架构

```
                    ┌──────────── 编排器 Orchestrator ────────────┐
  输入(图/视频帧) ─▶│  路由 → 调度分支 → Fusion 融合 → 判决+计时   │─▶ {异常分, 掩膜, 框, 类型, 耗时}
                    └─────────────────────────────────────────────┘
  ── 热路径(计时, 小模型, <200ms) ─────────────────────────
     ① 纹理/外观异常   EfficientAD / PatchCore (anomalib)
     ② 零样本冷启动     AnomalyCLIP / WinCLIP (CLIP 底座)
     ③ 缺件检测         轻量 YOLO + 模板比对
     ④ 顺序/逻辑校验    部件检测 → 规则引擎 (count/order/position)
     ⑤ 尺寸测量         经典 CV (标定 + 轮廓测量)
  ── 冷路径(不计时, LLM) ───────────────────────────────────
     缺陷报告生成 · 反馈分诊 · 合成数据指导 · 逻辑语义复核
```

**热/冷路径分离原则**:赛题只对检测推理计时,不对报告/反馈/合成计时。把所有重模型(LLM/Diffusion)放冷路径,既拿新颖性分,又不丢时间分。

## 4. 模块划分

每个模块单一职责、接口清晰、可独立测试。分支统一接口:`Branch.infer(image) -> BranchResult{score, mask, boxes, type, latency_ms}`。

| 模块 | 文件 | 职责 | 依赖 |
|---|---|---|---|
| 编排器 | `core/pipeline.py` | 路由 + 调度 + 计时 + 延时守卫(超预算跳过慢分支) | 各分支, fusion |
| 融合 | `core/fusion.py` | 多分支分数 → 最终异常分/类型/定位;阈值标定 | - |
| 少样本适配器 | `core/fewshot.py` | `fit_fewshot(normals, defects)`:建记忆库/标阈值/轻量 Cut-Paste 扩充 + 判别头 | 分支①②③ |
| 主动学习闭环 | `core/active_learning.py` | 反馈 → 入记忆库/重标阈值/微调轻量头;记录前后对比 | fewshot |
| 纹理异常分支 | `branches/texture_ad.py` | EfficientAD/PatchCore,输出异常图+分数 | anomalib |
| 零样本分支 | `branches/zeroshot_clip.py` | AnomalyCLIP/WinCLIP,文本提示零样本 | open-clip |
| 缺件分支 | `branches/missing_part.py` | 轻量 YOLO + 模板比对,输出存在/缺失部件 | ultralytics |
| 逻辑校验分支 | `branches/logic_check.py` | 基于部件的规则引擎(数量/顺序/位置),针对 LOCO 逻辑异常 | missing_part |
| 尺寸分支 | `branches/dimension.py` | 标定 + 轮廓测量,检尺寸偏差 | opencv |
| LLM 报告 | `llm/report.py` | 热力图+结果 → 自然语言缺陷报告 | Qwen-VL/API |
| LLM 分诊 | `llm/triage.py` | 辅助分诊操作员反馈、建议标签 | Qwen-VL/API |
| 合成数据 | `llm/synth.py` | 重型 Diffusion 缺陷合成(训练期,可选) | diffusers |
| 部署提速 | `deploy/export.py` | OpenVINO 导出 + 2500² 切块 + 延时基准 | openvino |
| Web Demo | `demo/app.py` | Gradio:检测 → 标漏检 → 看在线更新 | gradio |
| 评测 | `eval/protocol.py` | 官方协议复现 + 跨域泛化 + 算分 | - |

## 5. 数据流

- **准备期**:下载公开集 → (可选)重型合成增强 → 预训练/构建各分支模型 → 导出权重。
- **评测期(评委机器)**:`fit_fewshot(100 正常, 30 缺陷)` 配置分支+阈值+轻量合成判别头 → 对 1000+ 测试图 → 编排+融合 → 结果 + 耗时。
- **在线**:操作员标漏检/误检 → `active_learning` 更新模型 → 效果对比。

## 6. 数据集

全部公开可下载,开发与泛化验证用:

| 数据集 | 用途 |
|---|---|
| MVTec AD | 主基准(15 类),外观/纹理异常事实标准(赛题点名) |
| MVTec LOCO AD | 逻辑/缺件/顺序异常 — 支撑"全类型"里最难的部分 |
| VisA | 跨数据集泛化验证 |
| DAGM 2007 | 纹理缺陷(赛题点名) |
| MPDD | 金属件缺陷,最接近"中框/电池"工业组件场景 |

外加 `eval/protocol.py` 自建模拟评测协议:从某类抽 100 正常 + 30 缺陷迁移,在剩余样本测;并做跨类/跨数据集泛化测试。

## 7. 错误处理 & 测试

- 分支隔离:单分支抛异常返回 None,融合自动忽略,不拖垮整体。
- 热路径延时守卫:累计耗时超预算时跳过剩余慢分支,保证 <200ms。
- 输入校验:尺寸/通道/格式不符时归一化或明确报错。
- 每分支带极小样例单测(几张图);`eval/protocol.py` 作集成测试;`deploy/` 延时基准作硬门槛。

## 8. 技术栈

Python 3 / PyTorch 2.4 (cu121) · anomalib · open-clip(AnomalyCLIP/WinCLIP)· ultralytics YOLO · OpenCV · OpenVINO · Gradio · Qwen-VL 或 API(冷路径)· diffusers(可选)。
环境:RTX 4060 Laptop(8GB)+ 服务器(更大训练任务)。

## 9. 范围边界(YAGNI)

- **不做**:完整产品级前后端、云端部署、与赛题无关的重构。
- **核心不依赖**重型 Diffusion 合成;它是可选 novelty。
- 视频**不做**复杂时空网络;逐帧 + 时序平滑 + 逻辑分支即可。
- LLM **不进**计时主路径。
