# 使用说明 —— AOI 实时在线 AI 质检系统

## 1. 环境

- Python 3.8+,PyTorch 2.4(有 GPU 自动使用 CUDA,无 GPU 可跑但延时不达标)。

```bash
pip install -r requirements.txt
```

> torch 由系统环境提供;requirements 含 timm / numpy / Pillow / opencv-python /
> open_clip_torch / gradio / pytest。

### 可选:VLM 类型归属(推荐开启,但**不是必需**)

系统的缺陷类型归属有两条路:VLM 监督的类型头(主路,准确率高)与启发式(兜底)。
主路**只在迁移阶段(不计时)**调用一次外部视觉语言模型给那 30 张缺陷图打类型标签,
标签会被蒸馏成一个几十字节的质心表;**推理阶段完全不联网、不调 API**。

**API key 已内置,开箱即用,无需任何配置。** 如需换用自己的 key,设置环境变量
`DASHSCOPE_API_KEY` 即可覆盖内置值。

**无外网、调用超时、返回不可解析 —— 任意一种情况系统都会自动退回启发式,
检测与定位精度完全不受影响。** 评委机器无外网可直接运行,无需任何改动。

迁移阶段的额外开销:每个产品约 30 次调用,合计约 1 分钟、约 ¥0.06。

## 2. 提交入口(评委评测用)

```bash
python submit.py --normal <正常图目录> --defect <缺陷图目录> --test <测试目录> --out result.csv
```

- `--normal`:约 100 张正常图
- `--defect`:约 30 张缺陷图(若同目录下有同名掩膜,会自动用于训练监督分割头)
- `--test`:待测图片**或视频**,逐个输出判决
- 按图尺寸自动路由:长边 ≥1024 → **大图路径**(`CompetitionLargeDetector`,赛题 2500²
  图像走的就是这条);否则走常规小图路径。

无样本冷启动(赛题"少样本或无样本"):

```bash
python submit.py --zeroshot --class-name <品类> --test <测试目录>
```

> **离线可用性说明**:该路径依赖 CLIP 权重(约 571MB),**未包含在默认离线包中**。
> 赛题会提供 100 张正常图 + 30 张缺陷图,**少样本才是评分路径,其所需权重已全部离线打包**,
> 无外网可直接运行。若确需在无外网机器上使用无样本路径,先在联网机器执行
> `python scripts/pack_offline_weights.py --with-clip`,再把 `models/hf_cache/` 一并拷贝过来。
> 未打包时该路径会给出明确提示并退出,不会静默崩溃。

## 3. 编程接口

赛题场景的核心类是 `CompetitionLargeDetector`:

```python
import torch
from aoi.competition import CompetitionLargeDetector

det = CompetitionLargeDetector(device="cuda")

# 现场迁移(不计时):100 张正常 + 30 张缺陷 + 缺陷掩膜
#   normals / defects: List[Tensor(3,H,W)],float,[0,1]
#   masks:            List[np.ndarray(H,W)],{0,1}
det.fit_fewshot(normals, defects, defect_masks=masks)

# 推理(计时,目标 <200ms/图)
out = det.locate(img)                 # img: Tensor(3,H,W) 或 (1,3,H,W)
out["is_defect"]    # bool  是否缺陷
out["score"]        # float 异常分
out["defect_type"]  # str   赛题 5 类之一
out["mask"]         # np.ndarray(H',W') {0,1} 像素级缺陷掩膜
out["boxes"]        # List[(x,y,w,h)] 检测框
```

### 回溯检测逻辑(赛题要求)

```python
trace = det.explain(img)     # 冷路径,不计时,不影响 locate() 热路径
```

返回该图走过的**完整判定链路**:EAD 原始分与阈值、DINO 与 EAD 的 z 分及由谁主导判决、
灰区救援是否触发、类型归属由哪条路给出及各分支 z 分、定位管线依次生效了哪些模块、
本次实测延时。

### 反馈闭环(自学习)

```python
from aoi.active_learning import ActiveLearningLoop

loop = ActiveLearningLoop(det, normals, defects, masks)
loop.feedback(img, is_defect=True, mask=gt_mask)   # 操作员标记漏检
loop.feedback(img, is_defect=False)                # 操作员标记误检
```

两类反馈都走**跳过 EAD 学生重训**的快路径:单轮 1193s → 251s,且实测精度不劣于全量
重训(误检反馈上快路径反而更好,+0.326 vs +0.269)。依据见
[`aoi/active_learning.py`](../../aoi/active_learning.py) 的说明。

### 视频输入(逐帧 + 时序平滑 + 事件聚合)

```python
from aoi.video import VideoDetector, read_video_frames

frames = read_video_frames("clip.mp4", size=320, stride=2)
vd = VideoDetector(det, smooth_window=3, min_event_len=2)   # det 须已 fit_fewshot
out = vd.process(frames)
# out["events"] = [(起始帧, 结束帧), ...];起始帧即"早期拦截"点
```

`min_event_len` 去除单帧误报尖峰;事件起始帧实现不良的早期拦截。

## 4. 数据准备(开发与泛化验证用,评测非必需)

公开数据集放到 `data/` 下:

- **MVTec AD**:`data/mvtec/<类别>/`,结构 `train/good/*.png`、`test/good/*.png`、
  `test/<缺陷>/*.png`、`ground_truth/<缺陷>/*_mask.png`

- **Real-IAD**(pcb / phone_battery 等真实产线数据):`data/_dl/realiad/`

### Web 演示台(推荐:完整工作流的可视化入口)

```bash
PYTHONPATH=. python scripts/make_demo_data.py    # 一次性:生成演示数据集(5个产品,含对照答案)
PYTHONPATH=. python scripts/app.py --port 7860   # 浏览器打开 http://<主机IP>:7860
```

四个页签对应赛题完整工作流:

| 页签 | 做什么 |
|---|---|
| **① 迁移学习**(不计时) | 选产品或**系统文件框选三组图**(正常/缺陷/掩膜,掩膜按文件名自动配对)→ 开始迁移 |
| **② 在线检测**(计时) | **资源管理器式树形面板鼠标勾选**待检图,或系统文件框上传本机任意图片 → 结果画廊(红=预测)+逐图明细+准确率/延时汇总+检测逻辑回溯 |
| **③ 操作员反馈**(自学习) | 选中判错的图 → 标真实情况 → 提交。VLM 当场说出缺陷现象;界面直接展示**反馈前后分割头权重指纹与阈值**的变化;救不回时如实告知原因 |
| **④ 交付汇总** | 方案、成绩、方法论、未达成项 |

数据根目录可在 ① 页签随意切换(任意包含 `<产品>/normal|defect|mask|test` 结构的目录),
不锁死演示集。

**报数口径**:所有成绩单只报赛题评分口径——**图级准确率 / 逐图含漏检 IoU /
框命中@0.5 / 单图延时**。项目内部规约禁止用 AUROC 汇报,因为它与赛题评分方式无关,
且会掩盖阈值选取带来的真实误报代价。

## 6. 输入约定

- 图像:`(3,H,W)` 或 `(1,3,H,W)`,float,范围 `[0,1]`
- `fit_fewshot` 接收 `(3,H,W)` 张量**列表**
- `defect_masks` 接收 `(H,W)` 的 numpy 数组列表,取值 `{0,1}`,与 `defects` 一一对应
- `locate()` 逐张调用(批量请自行循环)
