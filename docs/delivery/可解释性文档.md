# 可解释性文档 —— 可自学习的 AOI 实时在线 AI 质检

> 本文说明**系统实际采用的架构**、**每一处选型的实测依据**、以及**检测逻辑如何回溯**。
> 全文只用赛题评分口径报数:**图级准确率 / 逐图含漏检 IoU / 框命中@0.5 / 单图延时**。

---

## 1. 赛题协议决定的架构约束

赛题评测协议:提交代码后,评委用**未知产品(手机屏/电池/中框等)的 100 张正常 + 30 张
缺陷**在其机器上现场迁移,再对 1000+ 张测试图评测,单图 <200ms @ RTX 2060。

三条硬约束由此确定,它们是后面所有取舍的根源:

| 约束 | 来源 | 对设计的强制要求 |
|---|---|---|
| **跨未知域** | 测试产品保密 | 不能训练"手机缺陷检测器";目标域的"正常"必须在现场用那 100 张图即时建模 |
| **迁移不计时,推理计时** | 原文"测试集运行前…进行迁移学习" | 一切昂贵计算(训练、标定、外部大模型调用)**必须挪到 fit 期**;推理期只留必要前向 |
| **200ms/图** | 原文 | 热路径每增加一次骨干前向都要归因计时;判正常的图必须早退 |

**"迁移不计时"是本方案最重要的杠杆。** 系统把尽可能多的计算——EAD 学生训练、分割头
监督训练、SAM 门控标定、阈值标定、VLM 类型标注——全部压进 fit 期,推理期只剩薄薄一层。

---

## 2. 系统实际架构

```
locate(img)
  │
  ├─【检测层】predict(img)                          ← 唯一决定"是不是缺陷"的地方
  │    ├ EfficientAD 学生-教师(2 学生集成)          → 检测分
  │    └ DINOv2 图级 co-detector,z 分平等融合门     → 最终判决
  │
  ├─ 判正常且不在灰区 → **立即返回**(不算分割/SAM)   ← 生产大多数图走这条,延时主要节省
  │
  ├─【定位层】segment(img)
  │    ├ WRN50 浅层(1,2)@512 → 128² 特征格
  │    ├ 监督分割头(linear + conv 双头**联合训练**)
  │    └ SAM 受控精化(fit 期逐区域 OOF 门控,不达标不启用)
  │
  └─【类型层】掩膜产出后
       ├ VLM 监督类型头(fit 期蒸馏,推理零 API)      ← 主路
       └ 4 分支 z 分 argmax 启发式                    ← VLM 不可用时自动兜底
```

对应代码:[`aoi/competition.py`](../../aoi/competition.py) `CompetitionLargeDetector`。

## 3. 逐模块选型依据(全部为实测,非文献引用)

### 3.1 检测层主干 —— EfficientAD 学生-教师(`_EADBranch`)

**为何不是 PatchCore 记忆库**:记忆库方案在本项目早期版本中使用过,已**整体替换**。
原因是记忆库对"现场 100 张正常图"的覆盖度极度敏感,且推理期最近邻检索随库增长变慢,
与 200ms 预算冲突。EfficientAD 的学生-教师蒸馏把"正常"编码进网络权重,推理是一次固定
开销的前向,**延时与样本量解耦**——这正是赛题现场迁移协议需要的性质。

**2 学生集成**:多种子学生集成(教师共享)。实测工作类方差收窄约 2×、现场单次 fit 的
成绩下限 **+0.012**、均值零代价。fit 不计时所以训练免费。

### 3.2 检测层的第二只眼 —— DINOv2 图级 co-detector

**解决的问题**:EAD 单独判图级时,某些类目会系统性漏判。DINOv2 自监督特征提供一路
与 EAD **误差不相关**的判据,两路 z 分归一后取平等融合门。

**代价证据(负面实验也照实记录)**:曾在一次延时自适应中让 DINO 门被自动砍掉,
cable 类图级 acc 从 **0.811 崩到 0.171**。这条 -0.6 量级的实测代价确定了 DINO 门是
**不可裁剪**的组件,后续所有探针脚本都强制保留它。

### 3.3 灰区受控补检

EAD 判正常、但分数处于自适应灰区(≥ g × 阈值)且分割信号超线 → 翻正为缺陷。
g 与阈值线在 fit 期按"联合翻正条件零误翻"标定,守不住则整体禁用。
这是一条**只增加召回、不改变原判定边界**的补丁。

### 3.4 定位层 —— 浅层特征 + 双头联合训练监督分割

**特征层选择是扫描出来的,不是猜的**:主分割头只用 WRN50 **浅层 (1,2) @512**,得到
128² 特征格。全层扫描实测(`run_feat_res.py`)含漏检 IoU 均值 **0.305 → 0.449(+47%)**,
其中 pcb +53%、phone_battery +74%、pill +72%,且浅层**更快**(8ms vs 36ms)。
640 输入过犹不及。**精度和延时在这里方向一致**,是本项目少有的双赢改动。

**加深语义已判负**:拼接 layer3 深层特征的实验,精度未达门槛且延时 +70ms,
在 200ms 预算下不可接受,已封存。

**双头联合训练**:linear 头与 conv 头由"各自独立训 300 步"改为"作为整体联合训练"
(梯度同时流过两头,让它们协同分工)。这是本项目 ~12 个候选改动中**唯一通过验证**的:

| 指标 | 独立训 | **联合训** | Δ |
|---|---|---|---|
| 图级 acc | 0.909 | **0.920** | **+0.010** |
| 逐图含漏检 IoU | 0.506 | **0.511** | **+0.005** |
| 框命中@0.5 | 0.554 | **0.582** | **+0.028** |

零延时代价、不碰骨干、推理结构完全不变(仍是同一个 `_Ensemble`)。

### 3.5 类型层 —— VLM 监督的类型归属头(`aoi/type_head.py`)

**这是本方案在"可自学习"上的核心设计。**

原始做法是拿 4 个检测分支的 z 分 argmax 定类型。该做法**根本上是错的**,因为那些分数
是为**检测**设计的(EAD 对任何缺陷都强响应),不携带类型信息。实测正确分支只在 2/4 类
拿到最高分。

改进分三步,每一步都有实测:

| 做法 | 类型归属准确率 |
|---|---|
| 原始:检测分支 z 分 argmax | 50% |
| 改用**位置匹配**判别特征(掩膜位置上与正常图同位置比) | 58% |
| **VLM 在 fit 期打标签 + 质心分类**(单图提问) | 77% |
| **VLM 双图对比**(正常参考图 + 待判图) | **87%**(GT 掩膜离线上界) |

**双图对比为什么是结构性的、而不是提示词调参**:赛题 5 类里"缺件少件 / 尺寸偏差 /
逻辑错误"这三类**本质上是比较出来的**——没有参照物,模型无法判断"这里本该有个东西"。
实测中缺线被判成"色彩变化",正是因为模型只看到"这块颜色不一样",不知道那里本该有根线。
给一张裁在**同一坐标**的正常参考图后,该类从 5/12 提升到 9/12。

**为什么推理期没有 API 依赖**:VLM 只在 **fit 期(不计时)** 对那 30 张缺陷图各调用一次,
把标签蒸馏进一个几十字节的质心表;推理期只算 4 维位置匹配特征 + 最近质心,**零外网、
零 API、微秒级**。评委机器无外网也照常运行。

**降级链**:无 key / 无网 / 超时 / 标注失败 / 推理期异常——任意一环断开都自动退回
启发式类型归属,**检测与定位完全不受影响**。

### 3.6 反馈驱动的自学习闭环(`aoi/active_learning.py`)

操作员标记漏检/误检 → 样本入集 → 增量重拟合。

**关键工程决策(有实测支撑)**:EAD 学生**只在正常图上训练**,缺陷图仅参与阈值标定。
所以操作员反馈"漏检"(新增缺陷图)时重训学生纯属浪费。走跳过学生重训的快路径后:

- 反馈一轮耗时 **1193s → 251s**
- 安全边际实测:快路径对"误检"反馈的效果**优于**全量路径(+0.326 vs +0.269)

因此**两条反馈路径都走快路径**,这不是为省时间牺牲精度,是实测更好。

## 4. 检测逻辑如何回溯(赛题明确要求)

`CompetitionLargeDetector.explain(img)` 返回单张图的**完整判定链路**,包括:

- EAD 原始分 / 阈值 / 是否越线
- DINO z 分、EAD z 分、**融合后由谁主导判决**
- 灰区救援是否触发、触发依据
- 类型归属:各分支 z 分、VLM 类型头是否就绪、最终类型由哪条路给出
- 定位管线依次生效了哪些模块(分割头 / SAM / 边界修正 / 级联)
- 本次实测延时

该方法位于**冷路径**,不参与计时,`locate()` 的热路径代码完全未被改动。

## 6. 已知薄弱环节(如实列出)

1. **逻辑错误类明显更弱**(acc 0.704 / IoU 0.192)。且 LOCO 官方定义是"计数/位置/搭配
   错误",与赛题原文"逻辑错误(如顺序错误)"是否同义**尚不确定**——"顺序"可能指
   2500² 图像由 4 块 1024² 拼接的空间顺序,也可能指产线装配时序。此问题已列入
   给出题方的问题清单,在得到答复前不宣称已覆盖。
2. **尺寸偏差类无公开数据可验证**。该分支已实现,但没有真实标注数据支撑其成绩,
   本文不给出任何未经验证的数字。
3. **微小缺陷(pcb 量级)是主要拉分点**(IoU 0.300),已定位为薄弱项。
4. **延时仅在 RTX 4060 Laptop 上实测**,2060 真机待验。持续满负载 1000+ 张的热漂移
   也尚未验证——fit 期的延时标定是在相对冷的 GPU 上做的。

## 7. 方法论:所有改动如何被接受或拒绝

本项目对每一个候选改动执行统一判据(**零回退纪律**):

> 在真实留出/OOF 数据上,`median(Δ) ≥ 0.005` 且 `mean(Δ) > 0` 且过半类目为正
> 且 `min(Δ) ≥ -0.01`,才允许进入生产;验证为负立即回退并留档。

约 12 个候选中**仅 1 个通过**(双头联合训练)。被判负并封存的包括:INP-Former、
VisionAD、WRN-LoRA 微调、layer3 深层语义、AHL 异态代理集、FocalDice、GCAD-EmbedAE。

其中 **GCAD-EmbedAE 是一次真实的教训**:它在定位指标上有小幅正收益,被一度接入生产,
但后续用完整成绩单复测发现**图级 acc 从 0.902 崩到 0.703**——原因是当初的验证只测了
缺陷图上的 IoU,**从未测正常图上的误报率**。该改动已回退,并确认基线干净恢复。
这条教训写进了项目规约:**任何改动都必须用含正常图的完整成绩单验证,不能只看缺陷图。**
